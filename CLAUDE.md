# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Что это

Офлайновый генератор Ethereum HD-кошелька: создаёт 24-словную BIP-39 seed-фразу, XPUB для `m/44'/60'/0'/0` и депозитные адреса внутри одноразового Docker-контейнера без сети. Не сервер, не библиотека — набор одноразовых entrypoint-скриптов. Весь текст для пользователя (сообщения об ошибках, подсказки, README) на русском; держите этот язык в новом коде.

## Команды

```bash
chmod +x *.sh          # один раз после клона
./build-image.sh       # сборка образа — единственный шаг, которому нужен интернет
./self-test.sh         # весь набор тестов проекта
./generate.sh [N]      # production-генерация, требует ввести GENERATE вручную
./verify-recovery.sh [N]  # восстановление из seed, требует интерактивный TTY
npm run check          # node --check по всем entrypoint'ам, зависимости не нужны
```

`N` — количество адресов, 1..1000, по умолчанию 5.

Отдельного тест-раннера нет: `src/self-test.mjs` — это и есть весь набор, один детерминированный вектор (публичная фраза `test test ... junk`, ожидаемый адрес `0xf39Fd6e51aad88F6F4ce6aB8827279cffFb92266`) плюс сверка адреса из XPUB с адресом из приватного узла. Запускать точечно отдельный `.mjs` внутри образа:

```bash
docker run --rm --network=none --entrypoint=node ethereum-offline-keygen:1.0.0 src/<file>.mjs
```

### Две ловушки при локальном запуске

- **`npm run self-test` на хосте всегда падает.** Каждый entrypoint первым делом зовёт `assertNoExternalNetwork()`, а на обычной машине есть Wi-Fi — тест умрёт на «Обнаружены внешние сетевые интерфейсы». Это не поломка, а сработавшая защита; тесты гоняются только через `./self-test.sh`, то есть в контейнере с `--network=none`.
- **Скрипты запуска идут с `--pull=never`.** Без предварительного `./build-image.sh` любой из них просто не найдёт образ.

## Архитектура

### Двухстадийная модель — главное ограничение проекта

Внутри полностью офлайнового контейнера зависимости скачать невозможно, поэтому они ставятся заранее: `Dockerfile` в стадии `dependencies` делает `npm ci --omit=dev --ignore-scripts` и переносит `node_modules` в `runtime`. Runtime не устанавливает и не качает ничего. Практическое следствие: **любое изменение зависимостей требует пересборки образа при включённой сети**, и это единственная точка, где сеть вообще допустима.

### Офлайн-инвариант держится двумя независимыми слоями

1. Docker-флаги в shell: `--network=none`, `--read-only`, `--cap-drop=ALL`, `--security-opt=no-new-privileges`, `--pull=never`, `--log-driver=none`, лимиты CPU/RAM/PID, tmpfs на `/tmp`.
2. `assertNoExternalNetwork()` из `src/security.mjs` внутри процесса.

Слои дублируют друг друга намеренно. **Новый entrypoint обязан звать `assertNoExternalNetwork()` первой строкой** — исключение только у `src/derive-from-xpub.mjs`, который по замыслу исполняется на сервере в онлайне.

Блок из двенадцати docker-флагов скопирован в `generate.sh`, `self-test.sh` и `verify-recovery.sh`. Правка ограничений — это правка всех трёх файлов. Там же захардкожен `ethereum-offline-keygen:1.0.0`; при смене версии её надо синхронизировать в четырёх скриптах и `package.json`.

### Граница секретности определяет разделение файлов

Seed-фраза существует только в stdout контейнера и никогда не пишется на диск — отсюда запрет на перенаправление вывода, `--log-driver=none` и отсутствие volume/bind-mount где-либо. На сервер уезжает только XPUB, derivation path и master fingerprint. Поэтому файлы делятся так:

- `src/generate.mjs`, `src/verify-recovery.mjs` — работают с секретом, живут только офлайн, гасят буферы в `finally`.
- `src/derive-from-xpub.mjs` — публичная половина, шаблон для серверного кода, секретов не касается.
- `src/security.mjs` — общие инварианты: `BASE_PATH`, `parseAddressCount`, проверка интерфейсов, `wipeBytes`.

`verify-recovery.mjs` читает фразу только из stdin со скрытым эхом (readline с Writable-заглушкой вместо output) — не из argv и не из env, иначе секрет утёк бы в `ps` и в окружение процесса.

### Почему путь именно `m/44'/60'/0'/0`

`BASE_PATH` — это account-level узел, и `neuter()` берётся именно с него. Дети `/0`, `/1`, `/2` неукреплённые, поэтому сервер выводит адреса из одного XPUB без seed-фразы. Хардненный уровень на месте детей сломал бы всю схему. **`BASE_PATH` менять нельзя после выдачи первого адреса** — все ранее выданные адреса станут невосстановимыми по новому пути.

Криптографии своей в проекте нет: BIP-39, BIP-32, secp256k1 и адреса делает `ethers` 6.17.0, энтропия берётся из `node:crypto`. Не заводите самописные реализации.
